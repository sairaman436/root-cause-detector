# Terms and Definitions

| Term | Definition |
|------|------------|
| Acceptance Criteria | Measurable conditions that determine whether a feature has been successfully implemented. |
| Actor | A person or system that interacts with the application. |
| AI Recommendation | An evidence-backed suggestion generated by the AI module to assist decision-makers. |
| Audit Log | A chronological record of significant system events and user activities. |
| Business Rule | A policy or constraint that governs how the system behaves. |
| Complaint | A reported issue submitted during a rural survey for further analysis. |
| Dashboard | A visual interface displaying statistics, trends, alerts, and AI insights. |
| District Administrator | A stakeholder responsible for overseeing district-level operations and reports. |
| Evidence | Supporting data, including surveys, complaints, GPS locations, and photographs, used by the AI system. |
| Explainable AI (XAI) | AI techniques that provide understandable reasons for generated recommendations. |
| Field Officer | A user responsible for collecting surveys, complaints, and supporting evidence in the field. |
| Functional Requirement (FR) | A documented feature or capability that the system must provide. |
| GPS | Global Positioning System coordinates captured during field surveys. |
| Non-Functional Requirement (NFR) | A quality attribute such as security, performance, scalability, or usability. |
| Root Cause | The underlying reason responsible for recurring or related community issues. |
| Root Cause Discovery | The AI-driven process of identifying probable causes using collected evidence. |
| RTM | Requirements Traceability Matrix, which maps requirements to design, implementation, and testing artifacts. |
| Stakeholder | Any individual or organization with an interest in the project or its outcomes. |
| Survey | A structured data collection record containing observations, complaints, location, and supporting evidence. |
| System Administrator | A user responsible for system configuration, user management, security, and maintenance. |
| Use Case | A description of interactions between an actor and the system to accomplish a goal. |
| User Story | An Agile requirement describing a feature from the perspective of an end user. |
| Validation | The process of ensuring that data or functionality satisfies defined requirements. |
| Verification | The process of confirming that a system has been built according to specifications. |
