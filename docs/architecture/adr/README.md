# Architecture Decision Records

## Purpose

Stores formal Architecture Decision Records for decisions that affect platform behavior, operability, security, data governance, or long-term maintainability.

## Why It Exists

The approved architecture identified canonical decisions and trade-offs. ADRs keep those decisions traceable as implementation details evolve.

## Architecture Fit

Each ADR should capture context, decision, alternatives, trade-offs, consequences, ownership, and review date. Implementation work should reference ADRs when a design choice affects multiple services or platform contracts.

## Implementation Notes

Use this directory for durable decisions, not transient task notes. Superseded ADRs should remain in place and point to the replacing decision.
