# Coding Standards

## Purpose

Defines baseline coding expectations for implementation teams.

## Why It Exists

The project requires maintainable, modular, observable, and secure code across multiple languages and runtime boundaries.

## Architecture Fit

This document turns the approved engineering standards into repository-local implementation rules.

## Standards

- Keep business logic in owning modules.
- Do not bypass service contracts.
- Do not commit secrets.
- Use structured logs and correlation IDs.
- Add tests with implementation changes.
- Update documentation when contracts or behavior change.
- Version prompts, models, API contracts, and event contracts.
