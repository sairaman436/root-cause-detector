# Architecture Proposal Template

## Purpose

Use this template before making structural system changes.

## Required Content

### Summary

Describe the proposed architecture change and intended outcome.

### Scope

List included systems, excluded systems, and milestone boundary.

### Current State

Describe existing architecture, constraints, and pain points.

### Proposed Design

Define modules, data flows, APIs, events, storage, security, observability, failure handling, and deployment.

### Alternatives

Compare at least two credible alternatives.

### Tradeoffs

Explain cost, complexity, latency, operational burden, security risk, and future flexibility.

### Migration Strategy

Define rollout, compatibility, data migration, and rollback plan.

### Validation Strategy

Define tests, dashboards, runbooks, and acceptance criteria.

### Approval

List impacted review boards and required decision records.

## Anti-Patterns

- Proposing technology without operational ownership.
- Omitting failure modes.
- Deferring security or observability.
- Ignoring approved prior milestones.
